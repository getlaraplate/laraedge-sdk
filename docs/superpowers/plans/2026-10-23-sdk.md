# laraedge plugin SDK. Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. Tick each step when it is done, in the same work block.

**Status:** Closed (2026-10-23). Shipped; see "Delivery status" below.

**Goal:** the Apache-2.0 repository `laraedge-sdk` with the plugin protocol `laraplate.edge.plugin.v1`, both sides of
the handshake (Unix sockets and Windows named pipes), the manifest, a Go SDK for the Input, Processor and Output kinds,
a conformance suite and three example plugins, so that the agent's host plans can import it.

**Architecture:** protobuf definitions with committed generated code; a `handshake` package with the plugin side and
the host side (launch, handshake line, connect, process-tree hygiene); a `manifest` package (format, canonical JSON,
schema checks); an `sdk` package that turns three small Go interfaces into the gRPC services; a `conformance` package
and command that drive a plugin binary through the host side; `examples/` exercising all three kinds.

**Tech Stack:** Go 1.27 (as `laraedge`); new dependencies `google.golang.org/grpc` v1.84.0 (Apache-2.0),
`google.golang.org/protobuf` v1.36.12 (BSD-3-Clause), `github.com/Microsoft/go-winio` (MIT, Windows only; the latest
release at least 14 days old when Task 4 starts), `golang.org/x/sys` (BSD-3-Clause), and
`github.com/santhosh-tekuri/jsonschema/v6` v6.0.3 (Apache-2.0, already used by the agent) — approval requested with this
plan. Build-time only: `protoc` 36.1, `protoc-gen-go` v1.36.12, `protoc-gen-go-grpc` v1.6.2.

**Spec:** `../../../../docs/superpowers/specs/2026-10-22-laraedge-plugins-design.md` (stack root), sections 2-5, 6
(the parts the SDK owns: launch, handshake, process tree), 7, 8, 9 plan 1; parent
`../../../../docs/superpowers/specs/2026-10-12-laraplate-edge-agent-design.md` section 8.

## Global Constraints

- Apache-2.0; module `github.com/getlaraplate/laraedge-sdk`; never import anything from `github.com/getlaraplate/laraedge`.
  Permissive dependencies only; no CGO.
- Work on branch `develop`, merged into `master` through a pull request; commit only your own files; never push; no
  `Co-Authored-By` trailer; do not commit at the stack root.
- `gofmt -l .` empty, `go vet ./...`, `GOOS=windows go vet ./...`, `go test -race ./...`, `GOARCH=386 go test ./...`
  before every commit; table-driven tests; fakes over mocks; no sleeps for synchronisation.
- Platforms (parent 10.1.1): Linux amd64 and arm64, Windows amd64 (Server 2016 and later) tested; Linux armv7 builds.
- Protocol package `laraplate.edge.plugin.v1`; handshake line `1|v1|unix|<path>` or `1|v1|npipe|<name>`; cookie
  variable `LARAPLATE_EDGE_PLUGIN_COOKIE`; socket directory `0700`, socket `0600`; Windows pipe ACL granting only the
  current user; handshake within 10 s; messages up to 16 MB; deadlines `Info` 5 s, `Configure` 10 s, `Probe` 30 s,
  `Send` 30 s (enforced by the host, honoured through `ctx` by the SDK).
- Output outcomes exactly: `ACCEPTED`, `DUPLICATE`, `RETRY_AFTER(duration)`, `SPLIT`, `REJECT_INVALID(reason)`,
  `SUSPEND_AUTH`. Input stream events: `sample`, `answered(device)`, `health(connected, read_error kind)` with kinds
  `timeout`, `connection`, `exception`, `decode`. Plugins never emit birth or death.
- Configuration errors are `ConfigError{path, message}` and never contain a value; secrets never travel in the
  environment.

## Decisions taken in this plan

- **S1. Info carries the manifest.** `InfoResponse` has `name`, `version`, `protocol_versions` and `manifest` (the
  canonical JSON of `plugin.json`). The host compares canonical forms; the proto does not duplicate the schemas.
- **S2. Canonical JSON** (`manifest.Canonical`): objects with sorted keys, no insignificant whitespace, numbers as
  written, UTF-8 unescaped except where JSON requires. Used for the manifest and for hashing comparisons.
- **S3. Cookie value** is the constant `ea6f1c2b-laraplate-edge-plugin-v1`; protocols are passed in
  `LARAPLATE_EDGE_PLUGIN_PROTOCOLS` (comma-separated, preferred first) and the socket directory in
  `LARAPLATE_EDGE_PLUGIN_SOCKET_DIR` (Unix). The plugin picks the first host protocol it supports; with none it writes
  a reason to stderr and exits with code 3.
- **S4. Socket and pipe names:** Unix `<dir>/p<8 random hex>.sock`, failing with a clear error when the path exceeds the
  platform limit (104 bytes on darwin, 108 on Linux); Windows `\\.\pipe\laraedge-<pid>-<8 random hex>` with security
  descriptor `D:P(A;;GA;;;<current user SID>)`. The host removes leftover `*.sock` files in the directory before a
  launch; the plugin removes its socket on exit.
- **S5. Process tree:** the host side starts the plugin with `Pdeathsig: SIGKILL` and its own process group on Linux,
  in a job object with kill-on-close on Windows; other Unix systems have no parent-death guarantee (development only).
- **S6. Panics in plugin code** (the author's callbacks) are recovered per RPC: the RPC fails with gRPC `INTERNAL`, a line
  goes to stderr, the plugin keeps serving.
- **S7. Configure input:** the agent sends the input's section JSON (`id`, `connection`, `devices` with `points`:
  `signal`, `address`, `read`, `type`, `byte_order`, `unit`, `priority`) with secrets resolved; `sdk.DecodeInput`
  turns it into Go types. Processor: `id`, `observe`, `devices`, `config`. Output: `id`, `config`.
- **S8. Fixtures:** `conformance.json` next to the manifest:
  `{"input": {"valid": [<section>], "invalid": [<section>]}, "processor": {...}, "output": {...}}` for the kinds
  offered; the suite fails when a kind offered has no valid and no invalid fixture.

## Review Focus

- A long `data_dir` makes the Unix socket path exceed the platform limit: the host reports "socket path too long"
  with the length, not a bind error. Test in Task 4.
- A plugin that crashes before printing the handshake line: the host returns at once (not after 10 s) with the exit
  code and the last stderr lines. Test in Task 4.
- A plugin that prints other lines before the handshake line (an author's `fmt.Println`): refused with a clear message
  naming the unexpected line's first 80 characters. Test in Task 4.
- A stale socket from a killed plugin in the directory: the next launch works and the old file is gone. Test in Task 4.
- An author's `Send` that panics: the plugin answers `INTERNAL` and keeps serving the next `Send`. Test in Task 5.

## Delivery status (2026-10-23): shipped

All eight tasks are built on branch `develop`, each reviewed, then a whole-branch review and one fix wave. The
repository holds the protocol `laraplate.edge.plugin.v1` with committed generated code and a descriptor golden test;
the `manifest` package (canonical JSON, strict loading, offline validation without value leakage); the `handshake`

checks licences (Linux and Windows), generated code drift and govulncheck, and runs the conformance command on the
examples on every platform; the first CI run on PR #1 passed every test on Windows (the Windows code paths were only
compiled before it). Commits from `b34de59` to `e7dd94f`, and the closing commit. The default branch is `master`
(renamed from `main` at the user's request on 2026-10-23). Dependencies, approved 2026-10-23:
`google.golang.org/grpc` v1.84.0 (Apache-2.0), `google.golang.org/protobuf` v1.36.12 (BSD-3-Clause),
`github.com/Microsoft/go-winio` v0.6.3 (MIT), `golang.org/x/sys` v0.48.0, `golang.org/x/net` v0.60.0 and
`golang.org/x/text` v0.42.0 (BSD-3-Clause; x/net raised for GO-2026-6603, -6611, -6612, -6617),
`github.com/santhosh-tekuri/jsonschema/v6` v6.0.3 (Apache-2.0). The divergences from the plan and the spec, each with
its reason (the rulings are in "Controller rulings" below):

- **Contract additions.** One `Subscribe` stream per input instance and one `Process` stream per processor instance;
  a second concurrent stream is refused with `ALREADY_EXISTS` (R10). The plugin binary sits next to `plugin.json` and
  is named after the manifest name, `.exe` on Windows (R11). A valid processor fixture may carry `records` for the
  suite (R9). `--manifest` prints the canonical bytes plus a newline; hosts compare canonical forms (R7).
- **Socket rules as built (S4).** The path limit is `len(sun_path) - 1`: 107 bytes on Linux, 103 on darwin and the

- **Public names settled before v0.1.0 (R17).** Prefixed constants (`QualityGood`, `PriorityCritical`, `EventBirth`,
  `ValueKindFloat`), the protocol version as a plain string, `Input.Stop(ctx, instance)` bounded by the Shutdown
  deadline or 10 s after a stream ends, typed `ReadError` kinds. Inbound enums outside their range are refused.
- **Shutdown refuses new calls** except Info, Shutdown and health, and never calls `Stop` while `Run` of the same
  instance runs (Task 5 review, final review I1).
- **Generation** uses `module=` rather than `paths=source_relative` (R3); protoc 36.1 is pinned with its hash (R2).
- **Not done, deferred:** release of Output and Processor instances removed on reload (an optional `Release` RPC for

  dependent keywords, a deterministic back-pressure test, a weak output-join test, the Windows window between process
  start and job assignment). The tag `v0.1.0` waits for the merge into `master`.
- **Carried to the agent's host plans:** offline validation sees `secret://` strings (resolve or skip them first); on
  Linux the plugin's own children survive the agent's sudden death (systemd `KillMode=control-group` is the backstop);
  stderr writers must drop, not block; the agent splits stderr into lines and truncates them; `max_memory` on Windows
  needs a handle by pid; a dedicated user per plugin conflicts with a 0700 socket directory owned by the agent's user;
  a refused re-Configure leaves the instance unconfigured; poll health with `Check`, not `Watch`; treat `UNAVAILABLE`
  or EOF on `Shutdown` as the answer.

## Controller rulings (subagent-driven execution, 2026-10-23)

Every ruling the controller took while executing this plan, copied verbatim from its execution ledger, with what
each costs if wrong. The Delivery status above cites them by number. The plan text above keeps its original names
where R17 renamed them (`sdk.Good`, `Health(..., readError string)`): the code and the docs carry the new ones.

- R1 Ruling: sdk.Serve exits through a package-level exit function (os.Exit by default) that tests replace, so Shutdown can be asserted without ending the test binary — the plan asks for both "exits 0" and in-memory tests — cost if wrong: none.
- R2 Ruling: the CI `generated` job downloads protoc from the protocolbuffers/protobuf GitHub release whose `protoc --version` prints `libprotoc 36.1`; the implementer verifies the exact tag and asset name and pins them in one place (the script) — the plan names only the version — cost if wrong: a failing CI job, visible at once.
- R3 Ruling: generation uses `module=github.com/getlaraplate/laraedge-sdk` instead of the plan's `paths=source_relative` — source_relative would put the code under laraplate/edge/plugin/v1/, not pluginv1/ as the plan's go_package requires — cost if wrong: none.
- R4 Ruling: the fix round also covers Canonical rejecting invalid UTF-8 and lone surrogate escapes, and Load rejecting a manifest that Canonical rejects (duplicate keys) or whose keys differ in case from the field names — S1 relies on canonical equality to compare plugin.json with Info, so two different documents comparing equal is a correctness defect, not polish — cost if wrong: a stricter manifest reader.
- R5 Ruling: manifest keys unknown to this SDK version stay tolerated (only case-variants of declared fields are refused) — a newer plugin's manifest may carry optional fields an older host does not know; the canonical comparison with Info still catches any difference — cost if wrong: a typo in an optional new field goes unnoticed.
- R6 Ruling: the fix round also takes three of the review's minors, because the agent's host builds directly on them: Pdeathsig made robust by starting children from one dedicated, permanently locked launcher goroutine; Dial returning when the plugin exits; Wait joining the output copiers so no write lands after Wait returns — cost if wrong: a little more code in handshake.
- R7 Ruling: --manifest prints the canonical bytes plus one trailing newline (CLI convention); Info.manifest carries the canonical bytes without it; S1's "same bytes" means same canonical form, and hosts and the conformance suite compare canonical forms — cost if wrong: a byte comparison that forgets to trim.
- R8 Ruling: the conformance suite runs every plugin with its working directory in a fresh temporary directory (jsonl's fixture path is relative), never in the plugin's own folder — carried into Task 7 as a requirement — cost if wrong: none.
- R9 Ruling: amends S8 — a valid processor fixture may carry an optional `records` list (records sent to Process); when absent the suite uses its synthetic records; a processor that emits nothing fails processor.signals with a detail asking the author to supply `records` — keeps the check non-vacuous while not failing processors that react to other signals — cost if wrong: one optional fixture field. To be applied in the Task 7 fix round.
